# 绘语 · dsh-drawcraft

名字里的「绘」是出图与画布，「语」是提示词工程。一句话需求进来，出去的是能直接投喂给图像模型的提示词、配好姿势与服装的参考图，以及一张能在画布上继续接续创作的图。插件在 DSH 侧边栏中部的面板区（与「插件」「技能中心」同组）加一个入口，面板里选好目标模型方言、风格、画幅，写一句人话，剩下的交给对话模型——它输出结构化的画面拆解，插件负责拼装成目标模型真正认的语法。

## 安装

**DSH Desktop**：设置 → 插件 → 从 GitHub 安装，粘贴 `https://github.com/Vhow123/dsh-drawcraft`。

**命令行**（把 `desktop` 换成你实际的 profile 名）：

```sh
dsh plugin --profile desktop add github:Vhow123/dsh-drawcraft
```

装完重启宿主。侧边栏中部面板区出现「绘语」；插件页里能看到它的 provider 与 model 组件。

## 它解决什么

手写生图提示词有三个反复出现的坑：

1. **糊**：主体、动作、环境、光线、镜头、材质全挤在一句话里，模型只能猜。
2. **废词**：`masterpiece, 8k, ultra detailed, best quality` 这类词对现在的模型不起作用，只会稀释真正的描述。本插件在输出前统一剥掉。
3. **方言不对**：Midjourney 要 `--ar 3:2 --style raw --no ...`，Stable Diffusion 要逗号分隔的 tag 加独立负向词，GPT-Image 要自然语言且**不该**有负向词，nano-banana 要「保持什么、改变什么」的编辑指令。同一段描述换个模型就得重写。

## 六种目标方言

| 方言 | 面向 | 输出形态 |
| --- | --- | --- |
| `natural-en` | 通用英文 | 一段连贯的英文描述 |
| `natural-zh` | 通用中文 | 一段连贯的中文描述 |
| `gpt-image` | GPT-Image 系列 | 自然语言长句，无负向词，无质量词 |
| `midjourney` | Midjourney | 短语串 + `--ar / --style raw / --no`，原有 mj 开关会被剥离后重写 |
| `stable-diffusion` | SD / SDXL / Flux | 逗号 tag 串 + 独立负向提示词 |
| `nano-banana` | Gemini 图像编辑 | 保持/修改分离的编辑指令 |

## 画面拆解

面板右栏永远把结果拆成 11 个字段，每个字段点一下就能单独复制：

`主体 · 动作 · 环境 · 构图 · 光线 · 镜头 · 风格 · 色调 · 材质 · 情绪 · 细节`

这十一个字段同时是模型的输出结构：模型返回 JSON，插件做归一化与拼装兜底，所以模型跑偏时你看到的是缺字段，而不是一段没法用的长文。

## 三个方向

同一个面板里有三条互通的路径，产物都是同一份结构化结果，可以互相接力：

| 方向 | 入口 | 说明 |
| --- | --- | --- |
| 想法 → 词 | 写描述 → 「优化提示词」 | 主路径：把模糊想法整理成可执行提示词 |
| 图 → 词 | 把图拖进「把图片拖到这里」，或点「选一张图」 | 需要能看图的对话模型；倒推出同一套 11 字段与最终提示词，可继续改方言 |
| 词 → 改词 | 结果卡片里的「改一句」输入框 | 写「光线换成黄昏」「镜头压低一点」，只改你点名的字段，其余逐字保留 |
| 词 → 图 | 结果卡片右上「试一张」 | 走本机 `dsh-imagegen` 插件的生图代理，直接把当前提示词渲成预览图；没装该插件时给出提示而不是报错 |

反推与改一句都会消耗一次对话模型请求；试一张消耗的是图像模型额度。

出图前可以定两件事：**出图尺寸**（`跟随画幅` 或 1:1 / 3:4 / 4:3 / 9:16 / 2:3 / 3:2 / 16:9 / 21:9）与 **出图清晰度**（`渠道默认` 或 1K / 2K / 4K），都是比例与档位字符串，由 `dsh-imagegen` 按实际协议换算成像素。预览图点击即放大，右上角「保存」直接下载原图（含大图视图里的保存与关闭）。

## 参考库

面板左栏「你想画什么」下面多了一个**参考库**。它接的是 [ai-pose-gallery-zh](https://github.com/anhao/ai-pose-gallery-zh) 的中文参考数据，以下数量以索引 JSON 实测为准：

| 库 | 数量 | 种类维度 | 内容 |
| --- | --- | --- | --- |
| 姿势 | 1,439 | 体系 4 / 角度 5 / 分类 26 | 站、坐、蹲、跪、卧、趴、抱，每个姿势带配套深度图 |
| 服装 | 1,407 | 分类 8 | 整套穿搭：季节与场景分类 + 单品颜色标签 + 英文 Prompt 关键词 |
| 人像 | 1,499 | 分区 2 / 发长 4 / 发型 51 | 正脸参考与造型氛围，细分到具体发型 |

**缩略图用的是深度图**，不是白模缩略图：白模在深色面板里只是一团灰白块，看不出胯部朝向和四肢前后关系；depth 图保留立体轮廓。姿势库每条记录都能按 `img/depth/{id}.webp` 取到（抽样 25/25 命中，900×1200 WebP，15–19 KB）。

**种类直接列在面板上。** 选定姿势 / 服装 / 人像之后，下面会展开该库的种类维度：一律用可点的胶囊按钮，每维度先显示前 8 个，超出部分给一个虚线「+18 更多」，点开在同一块区域里滚动展开。原生 `<select>` 的选项列表由系统绘制，深色主题下会变成白底浅字，所以这里不用下拉框。点一下即筛选，筛选与关键词是 AND 关系，选中的取值永远排在最前。

搜「蹲 侧面」「针织衫」「长发」，点缩略图加入参考（最多 6 条），优化时它们的**中文名称与分类会被当作硬事实**写进 `动作 / 主体 / 材质 / 细节`，模型不再自己编人体结构。点结果里的深度图链接可以直接喂 ControlNet。

参考库一次给 24 张，底部有「24 / 1439」和「加载更多 +24」按钮；缩略图区域自己滚动，不会把面板撑长。

不克隆那个 1.16 GB 的仓库：只拉三份索引 JSON（合计约 2.2 MB）缓存在 `~/.dsh/cache/drawcraft-gallery/`，首次联网之后离线可用；图片按需走 jsDelivr 取单张，且钉死在上游 commit `ec7a81e`，上游再推新提交也不会让旧链接失效。

## 图生图

导入一张自己的照片，用参考库的姿势把它改出新姿态——这才是这套东西的闭环。

**怎么导入**：面板里 `Ctrl+V` 直接粘剪贴板里的图；或者拖进「主要参考图」框；或者点框选文件。第一张进主图槽，之后的自动排进右边的附加参考位，各带一个 `×` 可以单独删。上限是主图 1 张 + 附加 4 张，跟 `dsh-imagegen` 的 `/images/edits` 收的 `image` + `image[]` 一一对应。

**怎么出图**：选好姿势（它的中文名称会被写进提示词）、优化出提示词、粘上你的照片，右上角按钮会从「生成预览」变成「**图生图**」，点它。请求发给本机 `dsh-imagegen` 插件的 `/api/dsh-imagegen/generate`，`mode: "edit"`，你的照片走 `image`，附加参考走 `images`。

**身份保持**：图生图时会在提示词前面自动接一句前置指令（中文界面用中文，英文界面用英文），大意是「以第一张参考图为唯一主体，脸、发型、体型、肤色都不改，只调整姿态、服装与场景」。不接这句，模型会照着提示词重新画一个人，导入的图就白给了。这句只加在发出的请求里，不改面板上显示的提示词。

**姿势图当图像条件**（默认关闭）：勾上「把手上的姿势图也发过去」，当前选中的姿势图会被抓成内联 base64 一起发过去，最多占满四张参考位。深度图当附加参考会把画风往灰白模型偏一点，所以默认关着。

**深度图当主图怎么过审**（v1.3.1）：上游网关看到灰度/单色图会直接判 `upstream-rejected`，理由是「图片经过淡化处理、无法核实」——跟姿势无关，一张完全中性的标准站姿深度图也一样被拒；给它上伪彩色能救中性姿势，但救不了性感系（热力图把裸体轮廓放大了，改判 NSFW）。真正的解法是**换成等高线线稿**：量化为 16 层、取层间边界、描边加粗一像素，白底深灰线，画面里只剩线条。

| 输入 | 结果 |
| --- | --- |
| 灰度深度图（性感系 / 中性） | 都拒，186–191 秒 |
| 伪彩色深度图（中性） | 过，65 秒 |
| 伪彩色深度图（性感系） | 拒，156 秒 |
| 等高线线稿 1024 长边、1px 硬边 | 拒，193 秒 |
| **等高线线稿 1200 长边、抗锯齿灰线** | **过，67.8 秒** |

两个参数是生死线：长边压到 1024 就拒，线条是 1px 纯黑白也拒——3×3 盒式模糊成灰线、长边留 1200 才过。这条路径只用作**被拒后的兜底**，不再对用户自己传的图做预判。

勾着「主图被判违规时自动转线稿重试」（默认开）时，主图被上游判 `upstream-rejected` 会自动转成等高线线稿再发一次。**不做预判**——真人照片在高调棚拍里饱和度也很低，按灰度预判会把真人转成线稿，出来就是卡通。

**实测**：主图 = 服装库 `SPR-0001`，附加参考 = 姿势库 `full_sexy_P001_front` 的深度图，`gpt-image-2.6-flare`，29.8 秒出 1086×1448 一张，衣服保留、姿态换成参考里的 S 形站姿。

## 自己的生图模型

出图默认借本机 `dsh-imagegen` 插件的渠道，但**不装它也能用**：面板里「出图模型来自」旁边有个 `+`，点开就能填自己的 OpenAI 兼容端点。

- 填**地址**（`https://api.openai.com/v1` 这种，到 `/v1` 为止）、**密钥**、**模型名**（逗号分隔可填多个）。
- 点「测试并保存」会先存下来，再打一次 `GET {地址}/models` 看通不通，把上游真实返回的模型名列出来。
- 保存后它就出现在「出图模型来自」的下拉里，和宿主渠道并列，随时切换。

密钥存在 `~/.dsh/drawcraft-targets.json`，只在插件服务端读，**不会回给浏览器**——设置列表里只回 `sk-s****1234` 这种打码值和「有没有填」。生图请求由宿主转发：

| 模式 | 走哪条 |
| --- | --- |
| 文生图 | `POST {地址}/images/generations`，JSON |
| 图生图 | `POST {地址}/images/edits`，multipart：主图 `image`、附加参考 `image[]` |

上游回 `{data:[{b64_json}]}` 或 `{data:[{url}]}` 都认，后者插件会自己把图抓回来转 base64。

### 参考图里的透视装会被判裸露

服装库里有几件是半透明薄纱（例如 SUM-0192「黑色白色迷你包」）。这种图本身就能透出胸部轮廓，模型照抄成透视装，上游网关直接 400 content_policy_violation，提示语里写什么都没用。

插件现在会自动补一句「透视、薄纱面料一律做成不透明的实拍面料，领口与胸口不得透出皮肤轮廓」，把面料做实、版型保留；如果还是被拒，会带着这句再发一次。实测同一组参考图，原样两次全拒，加上这句两次全过。

### 画布出图为什么老出成动漫

三个原因叠在一起，v1.9.2 都改了：

1. **主图选错**。画布原来按节点顺序取第一张图当主体。姿势白模、深度图、服装人台排在真人照片前面时，模型就照着那个白模画，出来是 3D 素模或二次元。现在出图前给候选图打分（肤色像素占比：真人照 10% 以上，白模与深度图基本是 0），最像真人照片的那张才当主图。
2. **附加参考被当成画风样板**。服装库是 3D 人台渲染，姿势库是白模/深度图，模型会把它们的材质与光照一起抄。现在带附加参考时会明说「只取版型与姿态，不要复制肤色、材质、光照与渲染风格」。
3. **提示词太短**。只写一句「头发换成双马尾」，模型自己挑风格就挑了插画。现在默认补一条写实约束，提示词里明确要插画/动漫时才会让位。

点节点上的 `⚡` 出图时，会沿连线把所有上游都带上（照片 → 服装 → 姿势 → 提示词 这种链，点在最后一段也全带上），主图就是这条链上的第一张；要换主体就点 `◎`。画布上的图单击可以开大图，滚轮缩放、拖动平移、底部有「保存」。

提示词里写「图二换服装」时，顺序必须对得上：发送前会按连线重新编号（上游是图一，顺着线往下数），并把「附图编号：图1「…」、图2「…」」写进提示词，所以「图二」指的就是连线上的第二张。没连线的图退回按从左到右数。

还有一件事：画布上摆着五张图时，谁当主体以前是靠猜的。现在图片节点标题栏有个 `◎`，点一下变成 `◉`，这张就是主体，其余都退成参考。出图后结果节点底部会写「模型 · 尺寸 · 主图名字」，鼠标停上去还能看到参考图名字与完整提示词——出歪了一眼就能看出它拿了哪张当人。

深度图、白模这类单色灰图当主图还会被上游判成「淡化处理过的规避图」。被拒时插件会自动把它转成白底姿态卡重试一次（人形缩到画面 82%、四周留白、灰阶变深蓝线），结果节点上标「已转成姿态卡重试」。真人照片被拒是内容问题，不转，直接把原因报出来。

## 无限画布

面板右上角点「无限画布」，正文换成整块画布，随时点「回到绘语」切回去。画布和绘语共用同一套出图通道，选中的「出图模型来自 / 出图模型」两边都生效。

- **平移缩放**：拖空白处平移，滚轮以指针为中心缩放（20%–250%），工具条上有 `−` 滑杆 `＋`、`适配`（把全部节点缩放进窗口）、以及百分比按钮（点一下回到 100%）。双击空白处复位到 100% 并回原点。
- **小地图**：右下角一块，灰块是节点、蓝框是当前视口。点小地图任意位置，视口就挪过去。画布空的时候不占地方。
- **节点**：`＋ 加图`（也可直接把图拖进画布、或 `Ctrl+V` 粘贴——剪贴板里是文件就落文件，只有图链就自己抓回来）、`＋ 提示词`。拖节点头部移动，拖右下角改尺寸，头部 `×` 删除，`↓` 下载，`⇢` 把这张图/这段文字送回绘语继续优化。
- **让单个节点出图**：节点头部的 `⚡` 直接出——它把自己（图或文字）连同所有连进它的上游一起拿去生成，不用先去工具条挑。
- **出图**：点选一个提示词节点 + 若干张图（`Shift` 多选），按「用选中的出图」。第一张图当主图走 `image`，其余最多四张走 `images[]`，提示词取选中的文本节点。结果作为新节点落在右侧，并从每个输入节点连一条血缘线过来——线表示「这张图是从这几样东西生出来的」，不用手画。
- **按记录再出一张**：出图结果节点会记下这次用的提示词、模型、尺寸和参考图，头部出现 `↻`，点一下拿它自己当主图、按记下的参数再来一张，结果继续连在右边。节点底部一行小字就是这条记录。
- **画布自带的参考库**：工具条上有一个 `▤ 参考库`，点开就在画布左上角浮出一块面板——搜索框、全部/姿势/服装/人像、种类胶囊筛选、缩略图网格、`24 / 4345` 加「加载更多」，跟绘语里那块一模一样。区别是这里**点一张就直接落到画布上**，不用切页面、不用先下载，落下来就能拖线接到任意节点。面板只影响画布自己那一套搜索状态，绘语里已经搜好的列表不会被打乱。
- **喂给选中的节点**：面板里每张缩略图左上角还藏着一个 `⇢`——先选中**一个**节点再点它，参考就直接用上去：选的是图片节点就换成这张图（标题和标签一起换），选的是提示词节点就把「姿势名・标签」追加成新的一行，接着 `⚡` 出图就是「这张图 + 这段描述」。
- **从绘语参考库过来**：绘语那张缩略图左上角悬停会出现 `⇱`，点一下同样把该图抓成内联落到画布（并切到画布视图）。
- **选中**：选中的节点边框变亮，工具条显示「已选 N」。`Shift` + 拖空白处是**框选**，`Ctrl+A` 全选，`Esc` 取消，`Delete` 删除选中的全部节点和它们身上的线。
- **复制粘贴**：`Ctrl+C` 复制选中节点（连线一起），`Ctrl+V` 粘贴到右下 28px 处，id 重新生成，粘贴后直接处于选中态，可以连续 `Ctrl+V` 铺一排。
- **手动连线**：节点左右两侧各有一个白心蓝环的小圆点，一直显形——右边是出口、左边是入口。从出口拖到另一个节点上松手就连一条带箭头的曲线，从入口拖出去则反过来连；自己连自己、同一对连两次都会被忽略。拖动过程中是黄色虚线，落空会提示「没落到节点上」。连好之后**鼠标划过线条变红、点一下就删掉**。
- 端口是给「这张图 + 这句话」用的：图片在左、提示词在右，从图片右边拖到提示词左边，再点提示词的 `⚡`，这张图就会被当作主图发出去。
- **删连线**：线条外面套了一条 14px 宽的透明命中区，点一下这条线就删掉，不用去动两头的节点。
- **撤销重做**：`Ctrl+Z` 撤销、`Ctrl+Shift+Z` 或 `Ctrl+Y` 重做，工具条上 `↶` `↷` 是同一件事。栈深 40 步，节点、连线、视口都在里面；拖节点、平移这种连续操作只在抬手时记一步，不会把栈冲掉。
- **导出导入**：`导出` 存一份 `drawcraft-canvas.json`（节点含图，可以直接备份或换机器）；`导入` 读回来，会先确认再整体替换当前画布，坏文件只提示不覆盖。

图进画布会压到长边 768（约 60–120 KB），否则几张就撞上 localStorage 的 5 MB。真撞了配额时，这次改动退一步只保留排版（图上打「这张图读不出来」），不会让整张画布消失。

## 三页

面板顶部三个页签，各管一件事，不再挤在一栏里：

| 页 | 干什么 |
| --- | --- |
| **提示词** | 写想法、选方言风格画幅，把一段白话压成能用的提示词。右栏是结果、字段拆解、变体与历史。 |
| **生图** | 左侧再分「文生图 / 图生图」。图生图才有主体槽、附加参考、参考库与审核兜底开关；文生图连主图都不发，手边存着图也不影响。中间是提示词、模型来源、尺寸清晰度，右边是出图结果。 |
| **画布** | 无限画布：节点与手动连线、框选、复制粘贴、撤销重做、小地图、导入导出。 |

从哪儿出图都落到生图页，出完自动跳过去看一眼；提示词页只留「去生图 →」的跳转按钮，不在那儿堆结果。

## 用法

**提示词页**：侧边栏中部「绘语」→ 顶部选 provider / model（必须选一次，之后记住）→ 写想法 → `Ctrl+Enter`。右栏可直接改、复制、或从历史里翻回上一次。描述输入框右上角的「清空」把这段描述一次性清掉，不动你已经选好的方言、风格与画幅。

**生图页不用先优化**：提示词按「手改过的 → 优化结果 → 你写的想法 → 选中的参考名称」依次回退，只勾了姿势没写字也能直接出。开「图生图」时中间那块提示词留空就用提示词页那段，写了就按写的出。

**别让图掉进附加位**：主图槽空着时，第一张附加参考会自动顶上当主体；真掉进附加位也不会退化成纯文生图。纯文生图且没写想法时还会补一句写实约束，否则模型只拿到一句姿势名，会自己挑插画风。

**出不来图的时候**：被上游内容安全拒掉时，预览区那张图会压暗并标注「上一次的结果，这次没出图」——别把它当成新图。实测真人照片配「性感系」姿势（抱腿打开、骑乘位、挤胸系这些）基本每次都被挡，换「标准系」「上半身单人」的姿势，或者不传主图走纯文生图，32 秒左右就能出。

**Agent 工具**：对话里直接说「帮我写一个 xx 的生图提示词」，模型会调用 `optimize_image_prompt`；说「把它改成黄昏」这类微调，模型会调用 `patch_image_prompt`（只重写被点名的字段）。两个工具在没有任何面板打开时也能用，配置从 `~/.dsh/drawcraft.json` 读。

## 配置

- `~/.dsh/drawcraft.json`：provider / model / 方言 / 风格 / 语言 / 画幅 / 候选数，`/optimize` 带 `remember: true` 时写入。
- 浏览器 localStorage `dsh-drawcraft:v1`（旧键 `dsh-image-prompt-forge:v1` 会在第一次打开时自动搬过来）：面板上的选择与最近 24 条历史。

## 接口

| 路由 | 作用 |
| --- | --- |
| `POST /api/drawcraft/catalog` | 可用 provider/model 列表 + 方言/风格/模式目录 + 当前配置 |
| `POST /api/drawcraft/optimize` | 想法 → 词；`runId` 可中途 `/stop` |
| `POST /api/drawcraft/describe` | 图 → 词：`image.data` 传 base64 或 data URL，宿主持久化成附件再交给视觉模型 |
| `POST /api/drawcraft/patch` | 词 → 改词：`prompt` + `instruction`，未点名的字段原样保留 |
| `POST /api/drawcraft/stop` | 按 runId 取消 |
| `POST /api/drawcraft/config` | 读/写配置 |
| `POST /api/drawcraft/gallery` | 参考库：`action: search / random / libraries / kinds`；search 与 random 可带 `filters`（如 `{分类:'蹲姿'}` 或 `"分类=蹲姿,角度=侧面"`）；search 支持 `limit`（1–60）与 `offset`（0–5000）分页，响应带 `total / offset / limit`；kinds 返回各库的种类维度与计数 |
| `POST /api/drawcraft/targets` | 自带的生图端点：`action: list / save / remove / test`；`test` 会打一次 `GET {baseUrl}/models` |
| `POST /api/drawcraft/render` | 用自带端点出图：`targetId` + `prompt` + `mode`（`edit` 带 `image`/`images`），插件服务端转发，密钥不出本机 |

全部只接受本机同源请求。「试一张」默认不经过本插件：面板直接调用本机 `dsh-imagegen` 的 `POST /api/dsh-imagegen/generate`，所以没装生图插件时只是宿主那一路不可用；配了自带端点就走 `/render`。

## 开发

```bash
node --test test/*.test.js      # 引擎、画布存储与撤销栈、路由与工具契约单测（52 项）
node test/bare-import.mjs       # 裸加载验证：不重定向任何宿主包直接 import
node test/client-contract.mjs   # 浏览器半的槽位、词典与渲染钩子契约
node --check index.js client.js engine.js
```

`bare-import.mjs` 是本插件必须常驻的回归线：插件用 junction 链接进 profile，真实路径在 DSH 安装目录之外，Node 的 ESM 解析会从真实路径向上找 `node_modules`，够不到 `@deepseek-ai/*`。所以插件**不 import 任何宿主包**，工具定义用自带的 `defineTool` 最小实现（声明式参数表 → JSON Schema + 必填/类型校验），产出对象与宿主 `tools.register()` 期望的形状一致。

加载期诊断会写 `~/.dsh/drawcraft-load.log`：

```
2026-11-14T09:31:02.114Z module evaluated
2026-11-14T09:31:02.118Z apply() 被调用，webServer=true llm=true
```

有第一行没有第二行，说明模块起来了但没被 apply；两行都没有，说明 bundle 根本没被加载。
